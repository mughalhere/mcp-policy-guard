mcp-policy-guard

An MCP server hands a model a set of tools and, by default, trusts every call it makes. This sits between the two — deciding which calls run, which need a human, how often they may happen, and what the response is allowed to contain.

What it does

        
One call wraps the whole tools/call path. Your tool implementations don't change.

        

          

            
Default deny

            
A tool with no matching allow rule does not run — including tools added to the server later.

          

          

            
Argument-aware rules

            
Rules take a when condition, so the same tool can be permitted for one path and refused for another.

          

          

            
Confirmation gates

            
Single-use tokens bound to tool, arguments, and identity — or an out-of-band approve callback that keeps the authorising signal away from the model.

          

          

            
Layered rate limits

            
Global, per-tool, per-identity, and per-pattern budgets. Every bucket is checked before any is consumed.

          

          

            
PII redaction

            
Eleven builtin patterns plus key-based rules, applied to results, arguments, and audit records. Cards are Luhn-checked.

          

          

            
Audit and metrics

            
One JSONL entry per decision, to a file, callback, or several at once. A failing sink can never fail a tool call.

          

        

      

    


    

      

        
Scope

        

          Prompt injection is out of scope. This library governs tool
          execution, not model prompt integrity. It limits the blast radius of a call an
          injected instruction produces, but it cannot tell that call apart from a legitimate one.
          Pair it with input-side gating, and read the
          threat model
          before relying on it for anything that matters.
